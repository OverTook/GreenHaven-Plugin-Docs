## server.properties

전용 서버는 데이터 폴더의 `server.properties`(처음 켤 때 기본값으로 만들어짐)를 읽습니다. `키=값` 줄입니다.

```
name=봄바람 마을 서버
motd=봄 축제 진행 중! 매일 저녁 7시 낚시 대회
max-players=40
password=
address=0.0.0.0:7777
online-mode=true
listed=true
tags=초보 환영,농사
region=한국
```

| 키 | |
|---|---|
| `name`, `motd` | 게임의 서버 목록에 보이는 이름과 소개 |
| `max-players` | 동시 접속 (0: 제한 없음) |
| `password` | 서버 전체의 비밀번호 |
| `address` | 명령줄에 주소가 없을 때 들을 곳 |
| `online-mode` | 접속자를 공식 중앙 서버로 확인 (기본 켬). 끄면 이름을 말하는 대로 믿음: 시험, 닫힌 LAN |
| `listed` | (online-mode일 때) 중앙 서버의 서버 목록에 1분마다 알려 멀티플레이 › 서버 찾기에 보임 |
| `tags` | 쉼표로: 초보 환영, 농사, 낚시, 축제, 느긋하게, 롤플레이 |
| `region` | 한국, 일본 … |
| `owner` | 이 서버의 주인 (중앙 서버의 계정 id; GreenHaven+ 서버를 만들 때 정해짐). 그 사람만 게임의 서버 관리에서 설정을 바꿈 |
| `save-mode` | `sleep`(아침에만, 기본) / `live`(1분마다·나갈 때); 플러그인의 `World::set_live_saving`이 우선 |
| `resume-seconds` | 끊긴 플레이어를 그날 상태로 기다리는 초 (30) |
| `quit-warning` | 자기 전에 나갈 때의 경고; 플러그인의 `World::set_quit_warning`이 우선 |
| `tick-rate` | 월드가 1초에 몇 스텝 도는지 (기본 20, 1~20; 마인크래프트의 월드 틱). 플러그인의 [`Tick`](events#tick)은 기본 1초에 한 번, 요청해도(`Registry::tick_rate`) 이보다 자주는 아님. 주민은 이것과 상관없이 1초에 다섯 번 걸음 |
| `plugin-cpu` | 플러그인들의 CPU 예산, 초당 백만 명령 (0: 제한 없음, 기본). 아래 [CPU 예산](#cpu-예산) |
| `level-type` | 모두의 월드를 처음 만들 때의 생성기: `vanilla`(땅과 마을, 기본) / `flat`(평평한 풀밭) / `void`(아무것도 없음). [월드 만들기](world#월드-만들기) |
| `transfer-to` | 플러그인이 묻지 않고 플레이어를 보낼 수 있는 서버 (쉼표로, 아이디나 주소; `*` 어디든). [다른 서버로](#다른-서버로) |
| `transfer-key` | 서로 믿는 서버들이 같은 값을 두는 키: 보내는 데이터를 서명함 (비우면 받는 쪽에서 "확인 안 됨") |
| `http-allow` | 플러그인이 [바깥 요청](sdk#바깥-요청)을 보내도 되는 호스트 (쉼표로, `host` 또는 `host:port`; 비면 아무 데도 안 됨, 기본). 사설·루프백 주소는 그 주소 자체를 적었을 때만, 24시간 서버에서는 안 됨 |
| `transfer-names` | 이 서버가 불리는 다른 이름 (쉼표로: DNS 이름:포트, 별칭; `address`와 24시간 서버의 아이디는 언제나). 서명된 받는 서버가 이 중 하나가 아니면 그 표는 믿지 않음 |

### 다른 서버로

로블록스의 TeleportService, BungeeCord의 서버 옮기기처럼 `Player::transfer(to, data)`(`to`는 `host:port`나 24시간 서버의
`GS-` 아이디, `data`는 4 KB까지)와 `Server::transfer_all(to)`. 게임은 로비를 거치지 않고 지금 서버를 나가 그 서버에 보통의
접속으로 들어갑니다(그 서버의 중앙 서버 확인, 받을 파일 묻기, 버전, 인증서 고정 그대로). 따라가는 것은 계정과 `data`뿐입니다.

- `transfer-to`에 없는 곳, 또는 이 게임이 한 번도 가 본 적 없는 곳(서버는 무엇이든 말할 수 있으니)이면 게임이 묻습니다:
  이동 / 거절. 답은 게임을 끌 때까지 그 두 서버 사이에 기억됩니다. 닿지 못하거나 거절당하면 온 서버로 돌아갑니다.
- 받는 서버의 [`Join`](events#join--leave)에서 `transfer_trusted()`가 참인 것은 같은 `transfer-key`를 가진 서버가 이
  플레이어와 이 서버를 위해(서명된 받는 서버가 이 서버의 이름: `address`, 아이디, `transfer-names`) 1분 안에 서명한, 처음 쓰는
  표일 때뿐입니다(HMAC-SHA256: 이름, 보낸 서버, 받는 서버, 만료, 데이터). 같은 키를 가진 다른 서버에 갈 표는 여기서 믿지 않습니다. 아니면 아무
  게임이나 지어낼 수 있으니 보상이나 경기 결과로 믿지 마세요.
- `transfer_from()`은 보낸 서버가 자신을 부르는 이름: 24시간 서버는 아이디, 아니면 `address`(모든 주소면 빈 문자열).
  돌려보낼 때 그대로 `transfer`에 넣으면 됩니다. 예제 `plugins/portal`.

### 서버의 이동 검사

서버는 플레이어가 가는 곳을 다섯 가지로 검사합니다: `speed`(빠르기), `walls`(벽·건물 통과), `air`(공중·물 위·땅속에 2초 넘게),
`teleport`(걷기가 시작될 수 없는 곳에 나타나기), `reach`(도구의 칸이 손 닿는 거리 밖). 막힌 걸음은 되돌려 보내고 계정에 적어 둡니다.
새 이동 방식(비행 등)을 만드는 플러그인은 이것을 모두에게(규칙의 `checks.*`) 또는 한 사람에게만(`Player::set_check`) 끌 수 있고,
그러면 그 검사는 그 플러그인이 대신 합니다. 꺼진 검사는 서버가 켜질 때 로그에 한 줄로 나옵니다.
[이동 방식 만들기](moving#서버의-이동-검사) 참고.

### 서버의 규칙 패치 (`rules.d`)

플러그인 없이 서버의 규칙을 바꾸려면 데이터 폴더의 `rules.d/*.json`에 JSON 패치를 둡니다(이름 순서로, 플러그인이 등록한
것보다 먼저 깔림; 덮어쓰기는 [규칙 등록](rules#덮어쓰기-규칙)과 같음). 게임은 월드의 옵션을 `rules.d/_world.json`에 씁니다.

### GreenHaven+ 24시간 서버 (게임의 서버 관리)

GreenHaven+ 플랜으로 만든 24시간 서버의 `owner`는 그 플랜을 산 계정(중앙 서버의 계정 id)입니다. 그 사람이 게임의 **GreenHaven+ ›
구독 관리 › 서버 관리**를 열면 게임이 그 서버에 직접 묻고(`{"t":"manage"}`, 접속처럼 중앙 서버로 본인 확인), **일반** 탭에서 이름,
설명, 접속 한도(플랜 한도까지), 공개 범위, 비밀번호를 바꿀 수 있습니다. 저장하면 서버가 값을 확인하고 파일에 씁니다.
**서버를 다시 켜면 적용됩니다.** `owner`는 여기서 바꿀 수 없습니다. 중앙 서버는 어느 서버가 누구의 것인지만 알고 설정은 바꾸지 않습니다.

접속할 때 서버는 받을 파일을 알립니다: `<data>/packs/*.zip`(리소스 팩: 골라 받을 수 있음)과 플러그인의 `assets/`·`client.wasm`(꼭
받아야 함). 게임은 받을지 묻고, 끊기면 받던 곳부터 이어 받습니다.

## 샌드박스

- wasmtime (Cranelift). NaN 정규화와 연료로 **결정적**입니다: 같은 입력이면 늘 같은 결과.
- 이 문서의 ["gh" 함수](abi) 말고는 아무것도 못 합니다: 파일·네트워크·시간·난수 원천 없음. 시각은 `now()`, 난수는 `roll(k)`.
- 서버 쪽(`server.wasm`): 이벤트 한 번에 연료 5 000 000 명령, 실제 시간 약 50 ms(호스트 함수에 쓴 시간 포함: 길찾기를 수백 번
  하는 틱은 거기서 끊김), 메모리 16 MB (낚시의 `reel`은 한 번에 200 000, 시간 상한 없음).
- 끝나지 않는 반복이나 오류(panic, trap)는 **그 플러그인의 몫만** 없던 일이 되고 게임은 계속됩니다.
- 서버 전체로는 [CPU 예산](#cpu-예산)이 있습니다.
- `server.wasm`은 서버에서만 돌고 게임에는 가지 않습니다. 게임에 가는 것은 `client.wasm`뿐이며, 게임 안의 자기 샌드박스(호출
  한 번에 연료 5 000 000, 메모리 32 MB)에서 `"ghc"` 함수(보이는 것만)로만 돕니다([게임 쪽 코드](client)). 게임은 접속할 때 그런
  플러그인이 있다고 알립니다. `assets/`도 그림·소리·모델 원본만 씁니다.
- 휴대폰(안드로이드) 게임의 자체 서버는 플러그인을 하나도 쓰지 않습니다([휴대폰](plugin-json#휴대폰)). 플러그인이 있는
  서버에는 휴대폰으로도 들어갑니다. 게임 쪽 코드(`client.wasm`)는 PC에서 확인했습니다. Android(Cranelift JIT)와 iOS(Pulley 인터프리터)는 네이티브 라이브러리 설정만 되어 있고 아직 빌드해 확인하지 않았습니다.
- 이벤트 한 번에 1~2 µs (모듈은 월드마다 만들어 둔 채로 씀). 야생·땅의 아이템·방을 읽는 함수까지 가져다 쓰는 플러그인은
  이벤트마다 그 사본을 만들어 ~100 µs가 됩니다: 걸음마다 오는 `PlayerMove`에서는 특히 가볍게.

## 한계

- 게임은 아침(또는 `save_now`)에만 저장됩니다: 그 사이에 서버가 꺼지면 그날 일은 사라집니다 (`set_live_saving`이면 1분마다).
- 엔티티는 저장되지 않습니다 — `ModelEntity::set_persistent(true)`로 표시한 것만 월드와 함께 남습니다. 오래 남길 것은 `World::set` / `Player::set`이나 데이터 저장에.
- 동물용 새 건물 종류는 아직 없습니다 (헛간·닭장).
- 광산 층은 바위만 코드로 바꿀 수 있습니다 (벽과 사다리는 `mine_layout`).
- 규칙의 등록(블록·아이템·몬스터 종류 …)은 서버가 켜질 때([`Enable`](events#enable))만입니다. 월드 하나의 규칙 값은 돌아가는 중에도 `World::set_rule`로 바꿉니다([월드마다의 규칙](world#월드마다의-규칙가방시계-월드의-수명-미니게임-허브)).

## CPU 예산

서버는 플러그인이 쓰는 CPU를 연료(실행한 wasm 명령 수)로 셉니다. 호출 하나가 호스트 함수(길찾기 `World::path`, 지형 읽기
등: 연료는 한 명령이지만 서버의 시간을 씀)로 그보다 오래 걸렸으면 그 시간을 셉니다(1 ns = 연료 1: 1 ms = 100만).
server.properties의 `plugin-cpu`(초당 백만 명령, 0: 제한 없음)가 모든 플러그인의 몫이고, 코드가 있는 플러그인마다 똑같이 나눕니다. 플러그인마다 2초치까지 모아 둘 수 있어 잠깐 몰리는
것은 괜찮고(다른 플러그인이 부른 [호출](interop)은 불린 쪽 몫에서 나감), 다 쓴 플러그인은 다시 찰 때까지 **이벤트와 호출을 건너뜁니다**(구독하지 않은 것처럼: 취소할 수 있는 이벤트도 그 플러그인
없이 진행). 넘은 순간 서버 콘솔에 알립니다(1분에 한 번). 예산이 없어도 사용량은 세어, 게임의 서버 관리 › 플러그인에 플러그인마다
지난 1분의 사용량(몫의 몇 %)과 건너뛴 이벤트 수가 보입니다.

- 기계어로 도는 wasm은 대략 **1 밀리코어 ≈ 초당 100만 명령**입니다. `plugin-cpu=20`이면 플러그인들이 CPU를 많아야 약 20m 씁니다.
- GreenHaven의 24시간 서버는 요금제가 정합니다(잎사귀 20, 나무 50, 숲 100). `plugin-cpu`는 그보다 낮게만 정할 수 있습니다.
- 몫을 아끼려면: Tick은 기본 1초에 한 번으로 두고 꼭 필요한 것만 `Registry::tick_rate`나 `#[every]`로, 틱에서 플레이어마다 도는
  반복은 짧게, 큰 계산은 결과를 `World::set`에 남겨 두고 다시 쓰기.
